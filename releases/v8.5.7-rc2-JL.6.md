# MobHunting JL 8.5.7-rc2-JL.6 — Paper 1.21.11

Published consolidation of the JL.6 build already installed and validated on the server.
Active branch: `release/paper-1.21.11`. The server operator confirmed successful in-game
validation on Minecraft 1.21.11 on 2026-09-27.

## Changes since the published JL.3 release

- Reflective InfernalMobs compatibility for renamed main classes (`45b28d1d`).
- MyPet 4.x integration, built against MyPet 4.0.4 (`e624ba22`).
- Bounty lookup by sponsor, target and world group; validate withdrawal before saving.
- Failed payments/refunds leave bounties open; fix expiry/removal and cancellation amounts.
- BetterRevive final-death attribution to the original downing attacker, including projectiles.
  Revival clears attribution; finishing blows do not replace the attacker; repeated processing is prevented.
- CustomItemsLib dependency updated to `1.1.0-JL.11`.
- Nine bounty and thirteen BetterRevive regression tests.

The source consolidation is commit `0bdfca94`; the release tag also includes documentation.
JL.5 and JL.6 were developed locally before this publication. This release does not create
retrospective tags for intermediate local builds.

## Compatibility and build constraints

Runtime target: Paper 1.21.11. Other Minecraft versions are not validated by this release.
The inherited compile API remains Spigot 1.21.4 and `api-version` remains 1.21.
The build relies on the JL Maven dependency environment, including the custom parent and
CustomItemsLib 1.1.0-JL.11. MyPet is a local system dependency configurable with
`-Dmypet.jar=/absolute/path/to/MyPet-4.0.4.jar`; see the README.
Maven reports legacy dependency POM and overlapping manifest warnings, but the build succeeds.

BetterRevive attribution requires the original attacker online at final death and does not
persist across restart. No payment occurs on knockdown. No database migration is introduced.
